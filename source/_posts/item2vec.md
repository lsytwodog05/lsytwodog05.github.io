\[

\mathcal{L} = \sum_{s \in S} \sum_{l_i \in s} \sum_{-m \leq j \leq m, j \neq 0} \log P(l_{i+j} | l_i)

\]

| 符号 | 含义 |

| :--- | :--- |

| \(S\) | 所有用户行为序列的集合（整个数据集） |

| \(s\) | 单个用户的行为序列，例如 `[苹果, 香蕉, 橘子]` |

| \(l_i\) | 序列中的第 \(i\) 个物品（中心物品） |

| \(m\) | 上下文窗口大小（例如 `m=2` 表示看前后各 2 个物品） |

| \(l_{i+j}\) | 位于中心物品 \(l_i\) 前后 \(j\) 步的那个物品（上下文物品） |

| \(P(l_{i+j} \mid l_i)\) | **给定中心物品 \(l_i\)，预测上下文物品 \(l_{i+j}\) 出现的概率** |

> **对数据集里的每一个用户序列，对其中的每一个物品，取它周围窗口内的邻居物品，然后尽量提高“由中心物品能猜对邻居物品”的概率。**

如果把这个概率乘积取对数，并最大化它，就等价于让 **真正共现过的物品对** 在向量空间里更靠近。



假设有一条用户行为序列：

```

s = [A, B, C, D, E]

```

取 `m=1`，只考虑紧挨着的邻居。

- 以 `C` 为中心物品`l_i = C`）：

  - `j = -1` 时`l_{i-1} = B`，计算 `P(B | C)`

  - `j = 1` 时`l_{i+1} = D`，计算 `P(D | C)`

- 公式中会累加 `log P(B|C) + log P(D|C)`

对整个序列所有位置都这样做，然后把所有用户序列的结果加起来，这就是 \( \mathcal{L} \)。

训练时，我们调整物品的 Embedding 向量，**使得这个 \( \mathcal{L} \) 尽可能大**。

概率 \(P(l_{i+j} \mid l_i)\) 怎么算？

在原始的 Word2Vec 中，它是 **Softmax** 形式：

\[

P(l_{i+j} \mid l_i) = \frac{\exp(v_{l_{i+j}}^\top v_{l_i})}{\sum_{k \in V} \exp(v_k^\top v_{l_i})}

\]

其中 \(V\) 是所有物品的集合（词汇表），分母需要遍历所有物品，计算量极大。

**实际训练时**，Item2Vec 和 Word2Vec 一样，不会真的算这个 Softmax，而是用 **负采样（Negative Sampling）** 近似，只计算正样本（真正共现的物品对）和少量随机采样的负样本（不共现的物品对）的损失。



训练样本构造

1. **序列构造**：将用户的行为（购买、点击、浏览）按时间或 Session 组织成序列。

2. **正样本**：同一行为序列中共现的物品对。

3. **负样本**：按照物品的频率分布进行采样（非均匀采样）。

###  Skip-Gram with Negative Sampling（SGNS）

Item2Vec 采用的是 **Skip-Gram + 负采样** 的组合。

**Skip-Gram 的核心**：给定中心词（物品），预测其上下文（同一序列中的其他物品）。

**负采样的作用**：原始 Skip-Gram 的 Softmax 需要对所有物品计算，代价太高。负采样将问题转化为二分类——正样本（真实共现的物品对）打高分，负样本（随机采样的物品对）打低分。

**负采样概率**：物品被采样为负样本的概率与其出现频率的 **3/4 次方** 成正比——这能有效压低高频物品被过度采样的概率，让低频物品也有机会被学习到。

### 训练完成后如何使用？

得到每个物品的 Embedding 向量后，**两两计算余弦相似度**即可得到物品之间的相似度：

$$ \text{sim}(i, j) = \frac{v_i \cdot v_j}{\|v_i\| \cdot \|v_j\|} $$

线上服务时：用户点击/观看了某个物品 → 取该物品的 Embedding → 在向量索引（如 Faiss）中做 ANN 检索 → 返回 Top-K 相似物品。



### 优点

| 优点 | 说明 |

| :--- | :--- |

| **泛化能力强** | 相比 ItemCF 只依赖共现统计，Item2Vec 能突破邻域限制，挖掘更深层的相似关系 |

| **冷启动友好** | 只要有商品自身的属性数据，业务初期也能做推荐 |

| **可复用** | 训练好的 Embedding 可以复用到召回、粗排、精排等多个阶段 |

| **效果好** | 微软在 Xbox 音乐和 Windows 10 商店的实验中，Item2Vec 效果优于 SVD |

### 缺点

| 缺点 | 说明 |

| :--- | :--- |

| **仅利用共现信息** | 忽略了用户行为序列中的**顺序信息**（时序、先后关系） |

| **没有建模用户偏好强度** | 用户对物品的喜欢程度（评分、停留时长）没有被利用 |

| **需要序列数据** | 只能处理有序列型行为数据的场景 |

| **预处理复杂** | 物品维度选择、序列构造方式需要工程经验 |

##  工程实践要点

### 行为序列的构造方式

- **按 Session 切分**：同一个 Session 内的行为构成一个“句子”。

- **按时间窗口切分**：如过去 7 天的行为作为一个序列。

- **集合方式**：直接把用户的所有历史行为视为一个集合（无顺序）。

### 负采样策略

- **非均匀采样**：按物品出现频率的 3/4 次方分布采样。

- **数量控制**：通常每个正样本配 5~20 个负样本。

### 线上召回链路

完整的 Item2Vec 线上召回链路包括：

> 行为序列构造 → 样本窗口设定 → 负采样 → 向量训练 → ANN 建索引 → 线上 seed 扩展 → 过滤去重 → 融合排序 → 指标验证

##  常见面试题汇总

### 1. Item2Vec 的核心思想是什么？
**答**：Item2Vec 的核心思想是将 **Word2Vec** 从 NLP 领域迁移到推荐系统。它把**用户的行为序列（如点击、购买历史）** 类比为“句子”，把**物品** 类比为“单词”，通过分析物品在用户行为序列中的**共现关系**，为每个物品学习一个低维稠密的向量表示（Embedding）。训练完成后，向量空间中距离相近的物品，在用户行为上也具有较高的相似性。

### 2. Item2Vec 和 Word2Vec 有什么区别和联系？
**答**：
- **联系**：两者在**数学模型和训练算法上完全一致**，都采用 Skip-Gram 或 CBOW 架构，使用负采样（Negative Sampling）进行高效训练。
- **区别**：
  - **数据来源**：Word2Vec 输入是自然语言文本（有严格的语法和词序）；Item2Vec 输入是用户的行为序列（如浏览/购买记录）。
  - **序列特性**：Word2Vec 认为词序至关重要（窗口是滑动的）；Item2Vec 在标准实现中通常**忽略交互的时间顺序**，将用户历史视为一个**集合（Set）** 而非序列（Sequential），因此不建模先后顺序。

### 3. Item2Vec 为什么选择 Skip-Gram + Negative Sampling？
**答**：
- **选择 Skip-Gram**：Skip-Gram 是“给定当前物品，预测上下文物品”。在推荐场景中，用户行为序列中的物品两两之间通常都隐含“共现”关系，Skip-Gram 能更好地利用这种稠密的局部上下文信息，挖掘物品间的关联。
- **选择 Negative Sampling（负采样）**：标准的 Skip-Gram 输出层是 Softmax，需要对全量物品库（词汇表，可能上千万）计算概率，训练极慢。负采样将其转换为**二分类问题**（正样本 vs 负样本），只更新少量采样的负样本向量，极大降低了计算复杂度，使算法能在海量物品上运行。

### 4. Item2Vec 的训练样本是怎么构造的？
**答**：构造分为三步：
1. **序列构建**：将用户的行为日志按 **Session（会话）** 或 **时间窗口** 切割成多个序列。
2. **窗口滑动**：对每个序列中的每个物品（中心词），选取其前后 `m` 个范围内的物品作为上下文（正样本）。
3. **组成训练样本**：生成 `(中心物品, 上下文物品, 标签)` 三元组。由于标准 Item2Vec 忽略序列顺序，有些实现会直接将序列中**任意两个物品**都视为正样本对，或者随机打乱序列后再滑动窗口。

### 5. Item2Vec 的负采样是怎么做的？为什么不用均匀采样？
**答**：
- **做法**：按照物品在全量数据中出现的**频率分布**进行采样，频率越高的物品，被采样为负样本的概率越大。具体的采样概率为 \( P(w_i) \propto f(w_i)^{3/4} \)（3/4 次方调整）。
- **为什么不用均匀采样**：
  1. **均匀采样**会让模型花费大量精力去区分那些本来就很少出现的“长尾”物品，导致训练效率低下。
  2. **频率采样（非均匀）** 能让模型更关注难分的负样本（高频热门物品），因为这些物品本身在现实中出现的多，被误认为正样本的风险也高。3/4 次方的平滑处理能压低超级热门物品的采样概率，给中频物品留出学习空间。

### 6. Item2Vec 训练完成后，如何计算物品之间的相似度？
**答**：得到每个物品的 Embedding 向量 \( v_i \) 和 \( v_j \) 后，通常使用以下方式计算相似度：
- **余弦相似度**：\( \text{sim}(i, j) = \frac{v_i \cdot v_j}{\|v_i\| \|v_j\|} \)（最常用，归一化后只关注方向）。
- **点积（内积）**：若向量已归一化，点积等于余弦相似度；若未归一化，点积会受到模长影响。
在线上召回时，通常会对物品向量进行 L2 归一化，然后构建 **Faiss** 索引，通过 ANN（近似最近邻）搜索快速找到 Top-K 相似物品。


### 7. Item2Vec 相比 ItemCF（基于物品的协同过滤）有什么优势？
| 维度 | **ItemCF** | **Item2Vec** |
| :--- | :--- | :--- |
| **泛化能力** | 只能依赖**直接共现**统计，无法挖掘间接关联 | 通过**低维稠密向量**，能泛化到未共现但潜在相似的物品 |
| **应对稀疏性** | 长尾物品因共现少，相似度计算不准 | 通过全局向量空间，长尾物品向量也能被有效训练 |
| **可扩展性** | 相似度矩阵 \( O(N^2) \) 存储压力大 | 只需存储 \( O(N \times d) \) 的向量矩阵，易于上云 |

### 8. Item2Vec 有什么局限性？
**答**：
1. **忽略序列顺序（时序）**：将行为视为“集合”而非“序列”，丢失了用户的兴趣演变过程（如“先看手机，再看手机壳” vs “先看手机壳，再看手机”）。
2. **仅利用共现信息**：没有利用用户的显式反馈（如评分、停留时长、是否购买），无法区分用户是“喜欢”还是“偶然点击”。
3. **冷启动问题**：全新的物品（无历史共现记录）无法直接训练出有效的 Embedding。
4. **难以捕捉动态变化**：模型一般是离线全量训练，更新周期较长，无法实时捕捉秒级热点。

### 9. Item2Vec 适合什么业务场景？不适合什么场景？
**答**：
- **适合**：**强序列依赖**的场景，如**视频观看记录**（追剧）、**音乐播放列表**（歌单）、**电商加购/下单序列**、**资讯点击流**。这些场景中，物品之间的共现关系蕴含了丰富的用户偏好。
- **不适合**：**低频交互场景**（如婚庆、大额保险，用户一年买一次，序列太短）；**强时序敏感场景**（如预测用户下一步要买什么，顺序至关重要）；**冷启动严重的场景**（新物品占比较高）。

### 10. 线上用 Item2Vec 做召回，完整的链路是怎样的？
**答**：分为**离线**和**在线**两个部分：

- **离线阶段**：
  1. 收集用户历史行为日志。
  2. 构造用户行为序列（按 Session/时间切割）。
  3. 训练 Item2Vec 模型，导出所有物品的 Embedding 向量。
  4. 使用 Faiss 等工具对全量物品向量构建 ANN（近似最近邻）索引。

- **在线阶段**：
  1. 用户请求到达，获取用户的**实时历史交互物品**（种子 Seed，如最近 10 次点击）。
  2. 取这些种子的 Embedding 向量，在 Faiss 索引中进行向量检索（ANN 搜索）。
  3. 获取每个种子对应的 Top-K 相似物品候选集。
  4. 合并多路候选，过滤掉用户已交互的物品，按相似度加权排序后送入精排。

### 11. 如何处理 Item2Vec 的冷启动问题？（新物品没有行为序列）
**答**：可以通过以下几种方式结合处理：
1. **基于内容的初始化（Content-based）**：利用物品的属性信息（标题、类别、图片、描述）通过预训练模型（如 BERT、CNN）生成初始向量，融入 Item2Vec 的向量空间。
2. **热门/同类目平均值**：将该物品所属类目下所有老物品的 Embedding 的平均值作为其初始向量。
3. **随机初始化 + 快速更新**：分配一个随机向量，一旦该物品有少量曝光/点击，立即通过在线学习（或增量训练）微调向量。
4. **Hash 映射**：将物品的 ID 通过哈希函数映射到现有向量空间的一个固定位置（降级方案，效果通常不如前两者）。

### 12. Item2Vec 的 Embedding 维度怎么选？
**答**：维度选择是一个基于“经验+调参”的过程：
- **经验法则**：通常取 \( d = \text{ceil}(\text{vocab\_size}^{0.25}) \)（词汇量开四次方）或 \( d = \log_2(\text{vocab\_size}) \times 2 \)。例如，10 万物品通常取 64~128 维，1000 万物品取 128~256 维。
- **调参策略**：在验证集上评估 Recall@K 或 Hit Rate，维度太小欠拟合，维度太大容易过拟合且显著增加线上 Faiss 检索的内存占用和延迟。**工程上常用 128 维作为黄金起点**。
